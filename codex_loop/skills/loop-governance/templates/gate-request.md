# Gate 请求模板

> 使用说明：当需要用户做出决策时，使用此模板向用户展示 Gate 内容。
> Gate 记录在 `.ai/gates.yaml` 中，本模板是面向用户的展示格式。
> 用户只需要理解"是什么事"和"我需要做什么决定"。

---

## Gate 基本信息

| 字段 | 内容 |
|---|---|
| **Gate 编号** | G-T-XXXX-XXXXXXXX |
| **关联任务** | T-XXXX —— （任务名称） |
| **Gate 类型** | 审批 / 确认 / 选择 / 安装许可 |
| **当前状态** | pending（等待您的决定） |
| **创建时间** | YYYY-MM-DD HH:MM |
| **紧急程度** | 普通 / 重要 / 紧急 |

---

## 这是什么？

> 用一两句通俗的话说明：发生了什么事，为什么需要您做决定。

（如："开发者已经完成了登录功能的设计方案，需要您确认这个方案是否符合您的预期，
确认后就可以开始写代码了。"）

---

## 您需要决定什么？

> 明确写出需要用户做的选择，避免模糊表述。

（如："请确认：登录功能使用邮箱+密码的方式，是否满足您的需求？"）

---

## 背景信息

> 用非技术语言说明：这件事的来龙去脉，为什么到了需要您决策的节点。

（简要说明上下文，如：之前讨论了哪些方案、为什么选了当前方案、
这个决定会影响什么后续步骤。）

---

## 可选方案

| 方案 | 说明 | 效果 | 风险 / 代价 |
|---|---|---|---|
| A. （推荐方案名称） | （通俗描述） | （选这个会怎么样） | （有什么不好的地方） |
| B. （备选方案名称） | （通俗描述） | （选这个会怎么样） | （有什么不好的地方） |
| C. 暂不决定 / 以后再说 | 推迟这个决策 | （推迟的影响） | （推迟的风险） |

- （简要说明）

---

## 决策记录

> 以下由 AI 在用户做出决策后填写。

| 字段 | 内容 |
|---|---|
| **决策** | approved / rejected / deferred |
| **决策人** | user |
| **决策依据** | （用户的原话或总结） |
| **决策时间** | YYYY-MM-DD HH:MM |
| **执行状态** | approved_not_started / in_progress / completed |

---

## 特别注意

> 如果本 Gate 有特别需要用户关注的限制或约束，在这里列出。

- （如："批准后仍需您说'开始执行'才会动手，批准不等于自动开始"）
- （如："此 Gate 涉及修改核心配置文件，执行前会有二次确认"）

---

*Gate 是用户的决策，不是 AI 的结论。AI 只提供信息和建议，最终决定权在您。*
