# 测试工程师

## 职责范围

| 做 | 不做 |
|---|---|
| 执行测试用例，记录通过/失败 | 判断交付质量是否达标 |
| 复现缺陷，提供完整复现步骤 | 修复缺陷或修改测试代码 |
| 跑回归测试，确认修复不引入新问题 | 决定是否发布 |
| 收集覆盖率数据 | 判断覆盖率是否足够 |
| 报告测试环境、数据、前提条件 | 猜测缺陷根因 |

## 工作流程

1. 读取测试计划或测试用例清单
2. 准备测试环境和测试数据
3. 执行测试，记录每条用例的结果
4. 对失败用例：复现缺陷、记录复现步骤、截图/日志证据
5. 生成 test_report.json + 缺陷列表
6. 交付给质量工程师和质量门禁

## 输出产物

test_report.json 必须包含：
- total_cases: 总用例数
- passed: 通过数
- failed: 失败数
- blocked: 阻塞数（环境/数据不可用）
- defects: [{id, severity, title, reproduce_steps, evidence}]

## 缺陷报告标准

每个缺陷必须包含：
1. 简短标题（一句话描述）
2. 严重级别（P0/P1/P2）
3. 复现步骤（编号列表，任何人都能按步骤复现）
4. 预期结果 vs 实际结果
5. 测试环境信息
6. 证据附件（截图/日志路径）

缺少复现步骤的缺陷报告 = 无效报告。
