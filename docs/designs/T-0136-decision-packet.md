## 三、方案要点

- **形态**：每域 = 模板（可直接填用）+ 角色知识（谁负责/何时/怎么裁决）+
  门禁检查点（发布前强制校验），三要素最小交付，不做大而全
- **优先级**：P0 三项（容量/稳定性/迁移，面试题最密集且引擎最空白）→
  P1 两项（性能/一致性）→ P2 一项（架构方法含 DDD/发布策略/AI 边界）
- **范围裁剪披露**：D-05 一致性方案中任务卡所列「分布式事务」明确裁剪
  （仅提及 2PC/事务消息不展开，以幂等+补偿为主轴），如需补 TCC/SAGA
  指引可另行提出
- **边界**：仅新增模板与角色知识资产；hooks/ 零改动、内核零触碰、
  版本 bump 由落地任务执行
- **与既有资产关系**：复用防御演练（T-0129）与 SLO/error budget
  （T-0090/T-0093）作为演练机制与阈值推导输入，不重复建设

## 四、决策选项

### 选项 A：全量批准，按 P0→P1→P2 三批落地（推荐）

- 内容：T-0137~T-0142 全部落地，先 P0 批（T-0137/0138/0139）→ 验收 →
  P1 批（T-0140/0141）→ P2 批（T-0142）
- 收益：一次决策覆盖全部盲区，知识层在 3 个迭代内补齐
- 代价：三批累计实施工作量（约 S+M×4+L）；每批仍需独立 gate 批准

### 选项 B：仅 P0 批落地，P1/P2 观察后再定

- 内容：只批准 T-0137/0138/0139（容量/稳定性/迁移）
- 收益：最小先行验证，模板可用性经真实项目检验后再扩展
- 代价：P1/P2 盲区（性能/一致性/DDD）暂留

### 选项 C：暂不落地，设计文档归档

- 内容：T-0136 收口为设计交付，T-0137~T-0142 不立项
- 收益：零实施成本，方案可随时启用
- 代价：盲区持续存在，接管项目时仍需现场从零设计

## 五、推荐

**选项 A**（全量批准、P0→P1→P2 三批），理由：
1. 六域设计已互相关联（压测合格线依赖稳定性指标；迁移双写依赖一致性
   幂等），分批过久会导致知识层碎片化
2. 每批独立 gate 批准已保留用户控制权，不存在「一次授权全部执行」风险
3. 面试题覆盖的正是「接管所有 ZCode 项目」的核心工程能力，尽早补齐
   收益最大
