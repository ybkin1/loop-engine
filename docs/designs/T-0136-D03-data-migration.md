## 1. 设计目标

让 Loop 工程能指导项目完成两类高难度迁移：
- **存储级**：百亿表换存储引擎/换数据库（面试题 #13）
- **架构级**：单体→微服务拆分的数据边界迁移（面试题 #3）
核心关切：存量数据如何迁移、平滑迁移方案、异常回滚、数据不丢失。

## 2. 三要素设计

### 2.1 模板：`templates/migration/data-migration-plan.md`

**Part A — 迁移四阶段法（通用骨架）**
1. **准备期**：存量数据盘点（行数/大小/依赖）+ 停机窗口评估 + 校验方案设计
   （校验 = 全量比对 or 抽样 + 计数 + 哈希）
2. **迁移期（双写）**：
   - 双写开关（新老库同时写，写老库保底）
   - 存量全量搬迁（分批 + 断点续传 + 速率控制）
   - 增量追平（binlog/日志回放，追平延迟 < 目标阈值）
3. **校验期**：双库一致性校验（计数 + 抽样哈希 + 业务对账）+ 延迟追平确认
4. **切换期（灰度切流）**：
   - 读流量灰度：1% → 10% → 50% → 100%（每档观察指标）
   - 写流量切换：先切非核心写，再切核心写
   - 保留新老双写 T 天（回滚窗口）

**Part B — 回滚方案（面试题：迁移异常回滚）**
- 回滚触发条件预定义：错误率 > X / 校验不一致 > Y 条 / RT 恶化 > Z%
- 回滚动作：切回老库（读回切 + 写回切），新库数据保留可复盘
- 回滚验证：老库恢复服务 + 数据完整性复查
- 双写期 = 天然回滚窗口；切换完成后仍保留 T 天回滚期（反向同步）

**Part C — 数据不丢失保证（面试题：如何保证不丢）**
- 三层保证：① 双写幂等（唯一键/版本号，防重放）② 搬迁断点续传（批次
  记录 + 校验和）③ 增量追平水位（lag 监控 + 追平失败告警）
- 终极对账：切换后 24h 内新老库持续对账，不一致自动告警 + 补偿任务

**Part D — 单体→微服务拆分迁移（面试题 #3 专项）**
- 数据边界先行：先拆库表归属（每个服务只能访问自己的表），再拆代码
- 业务无感知策略：接口兼容层（旧接口代理新服务）+ 灰度放量 + 影子流量
  对比（新老逻辑双跑，结果比对）
- 迁移顺序：读多写少 → 读写均衡 → 写多读少（风险递增）

### 2.2 角色知识

**归属角色：system-architect（迁移方案）+ release-engineer（切换执行与回滚）
+ quality-engineer（校验设计）**

`agents/system-architect/references/migration-checklist.md`：
- 迁移必须有：双写方案 + 回滚方案 + 校验方案 三件套，缺一不可
- 百亿表场景强制：分批搬迁 + 断点续传 + 追平水位监控

`agents/release-engineer/references/migration-release-checklist.md`：
- 灰度切流档位必须逐档验证，禁止一步全量
- 回滚预案演练在前，切流在后

### 2.3 门禁检查点

1. [CHECK] 迁移方案文档存在（双写/回滚/校验三件套齐备）
2. [CHECK] 回滚触发条件预定义（量化阈值）
3. [CHECK] 灰度切流档位表（≥3 档 + 每档验证指标）
4. [CHECK] 数据校验方案（计数 + 抽样哈希 + 对账）
5. [CHECK] 回滚演练记录（注入异常 → 回滚 → 恢复）

## 5. 风险

| 风险 | 缓解 |
|---|---|
| 迁移方案过度复杂（小库也用四阶段） | 模板按数据量分级：小库单次搬迁，大库四阶段 |
| 双写一致性风险 | 幂等设计 + 校验 + 对账三层兜底 |
| 与 forbidden「migration」冲突 | 明确：本模板是**设计方法论**，实际迁移执行仍需用户单独 gate（外部边界） |
