# 升级协议（T-0134 P4）— 用户只在 4 类价值问题时被升级

> 授权模型 v2：用户接触面 = 输入目标 / 验收结论 / 随时说"停"。
> 技术不确定性由 loop 吸收（保守默认 + 回滚 + KNOWN_ISSUES 诚实标注），
> **不升级用户**。只有真正属于用户的价值判断才升级，且用选择题呈现。

## 升级的 4 类场景（唯一允许创建用户 gate 的场景）

| # | 场景 | 示例 | 呈现形态 |
|---|---|---|---|
| 1 | 产品取舍 | 方案 A（功能全但慢）vs 方案 B（精简但快） | 选择题 + 推荐选项 + 一句话理由 |
| 2 | 新目标 / 目标修正 | 用户中途改变要交付的东西 | 确认目标变更 + 影响说明 |
| 3 | 外部边界 | 进入真实业务项目 / 部署 / 数据库等 forbidden 效果 | 必须用户显式 gate（不可绕过） |
| 4 | 目标冲突 | loop 发现两个目标互相矛盾 | 呈现冲突 + 候选裁决 |

## 不升级的场景（loop 自己承担）

- 任务排布 / 依赖顺序 / AC 可测性 —— 机器自洽校验（T-0127）
- gate 裁决 —— 机器验证链（T-0133 quality_pair / CHECK_RECOMPUTE）
- 风险可接受性 —— 预定义容忍度 + 演练证明（T-0129）
- 中间 checkpoint —— 只落盘不打扰（rounds 日志）
- 修复轮次 —— 3 轮上限，默认不通过（缩小范围 / 回滚重做）

## 选择题形态（用户只需选 A/B/C）

每次升级呈现：场景一句话 + 2-4 个选项 + 推荐 + 一句话理由。
用户不需要理解机制细节，只需要做功能层面的选择。

## 规则层（永不因委托豁免）

- AGENTS.md / forbidden 语义 / EVIDENCE_ONLY_BOUNDARY / 外部边界
- 规则层变更 = 唯一允许在委托链外创建的用户 gate
