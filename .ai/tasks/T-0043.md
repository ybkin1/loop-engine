# T-0043: 角色能力认证体系 — v3.2

## Status
`active`

## Phase
S4-implementation

## 目标
让 11 个角色"切实发挥作用"——不能靠提示词宣称，要靠可验证的能力挑战。

## 核心设计（吸收 Qoder certification.ts 理念）

### 能力状态机
```
UNCERTIFIED → CHALLENGE_PENDING → CERTIFIED
                                   ↓ (degradation)
              CAPABILITY_DEGRADED ← REVALIDATION_REQUIRED
                   ↓
              ROLE_BLOCKED
```

### 每角色能力挑战（隔离 fixture 中执行）
- 质量工程师：3-5 个 seeded defects，必须全部检测到
- 开发工程师：按契约实现，不越界，lint/typecheck/test 全过
- 安全工程师：硬编码密钥 + SQL 注入 + XSS 必须检出
- 独立评审员：预埋 3 个代码缺陷，必须发现 P0/P1

### 降级规则
- 连续 3 次无证据 PASS → CAPABILITY_DEGRADED
- 应发现缺陷未发现 → REVALIDATION_REQUIRED
- 越权操作（开发者改架构）→ ROLE_BLOCKED
