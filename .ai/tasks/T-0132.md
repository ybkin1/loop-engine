# T-0132: 三层质量线程架构设计（candidate-only）

## 任务概述

将 loop 工程从"两层架构（会话 + 平级角色）+ 阶段终点质量门禁"升级为
**三层质量线程架构**：质量类 agent（quality-engineer / test-engineer /
security-engineer / independent-reviewer）作为独立线程，对**任意动作产出**与
**阶段产出**进行多轮质量校验，过程数据与阶段输出均有机器可验的校验闭环。
本任务为 candidate-only 设计：产出三层模型详设 + 防伪造机制设计 + 防锁死机制
设计 + 决策包交用户，不落地。与授权模型 v2（目标授权制）同源：质量线程全绿 +
机器检查全绿 = 自动推进，用户仅在目标/验收/否决时介入。

## 两个硬性设计约束（用户指定，不可弱化）

1. **防伪造 / 先射箭再画靶**：质量校验结论不得由 AI 自述产生。必须做到
   机器可复算（数字可复跑重现）、检验者不见预期（质量线程只读产物、不注入
   执行线程自述结论）、防倒填（产物哈希先行登记 + 时间戳链）、抽查复算
   （机器对质量报告抽样重算）。
2. **防异常锁死**：治理状态损坏时必须有跳出项目（break-glass）的恢复/解锁
   路径，不得让项目锁死。回滚必须**快照先行 / 范围分级 / 动作留痕**，不得
   无脑删（evidence 历史与代码产物不可因回滚丢失）。

## 业务范围

- **D-01 三层模型详设**：
  - 角色分组契约：执行线程组 / 质量线程组；隔离从"developer≠reviewer"
    扩展为"执行组≠质量组"全量（不同 subagent_id + 独立上下文）
  - SubagentManifest 质量配对 schema（quality_pair：每个重量执行 spec
    必须配对质量校验 spec，无配对 = 编排无效，机器可判）
  - 动作级分层伴飞：轻量动作（单文件/文档）→ hook 机器检查；重量动作
    （跨模块/契约/设计产出）→ 质量 agent 线程校验（校验对象=动作产物）
  - 多轮校验轮次协议（round protocol）：状态机
    PENDING→CHECKING→FOUND→FIXING→RE-CHECK→PASS；3 轮上限；升级默认
    **不通过**（缩小范围+KNOWN_ISSUES 登记 或 回滚重做），不转嫁用户
- **D-02 防伪造机制设计（硬约束 1）**：
  - 机器可复算：质量报告中的数字（测试数/覆盖率/lint error 数）必须能
    通过重跑命令复现；校验时复算而非信任报告
  - 检验者不见预期：质量 agent 的输入 = 产物文件本身，prompt 不含执行
    线程的"自述结论/预期结果"
  - 产物哈希先行登记 + 校验结果后附（时间戳链），防止倒填
  - 随机抽查复算：guard_health 扩展新维度，对质量报告抽样复算
  - verdict 必须引用可核验证据文件路径，无引用 = 无效 verdict
- **D-03 防锁死机制设计（硬约束 2）**：
  - 三级恢复路径（break-glass）：
    L1 项目内修复器（validate_state --repair / repair_continuity，
    状态可读但损坏时）；L2 治理外快照回滚（回滚前强制快照归档 → 回滚到
    最近健康提交 → 仅恢复治理文件，evidence 历史与代码产物不动）；
    L3 手工接管（loop_mode 切 MANUAL，用户/开发者直接编辑，规则层仍
    用户 gate）
  - 回滚三原则：快照先行（快照/归档当前状态后才动）/ 范围分级（只恢复
    损坏的治理文件）/ 动作留痕（回滚日志 + guard-events 事件）
  - 锁死预防：状态写入原子化（现有 executor 原子写对齐）+ 三文件一致性
    检测（T-0127 思路）+ 自治 checkpoint 心跳（每 checkpoint 校验状态，
    损坏即暂停自动走恢复路径，fail-stop 而非 fail-silent）
  - 恢复演练设计：防御演练中纳入"锁死恢复演练"——人为制造状态损坏 →
    验证 L1/L2 路径可用（可用性被证明，而非假设）
- **D-04 决策包**：三层模型 + 防伪造 + 防锁死的完整影响面/风险/落地建议
  交用户裁决
