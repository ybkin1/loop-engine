# Task T-0037: Codex 侧 Loop 工程候选实现

## User Outcome

在 `loop-engine-lab` 内构建只面向 Codex 的本地 Loop 工程候选实现，使 Codex 能根据项目意图选择软件工程素材，编排稳定专业角色，按阶段生成任务包、详细功能设计、质量/安全证据和人类可读交付包，并在未满足条件时阻断或请求用户决策。

## Scope

- 建立 Codex 侧的 Loop Core/Runtime 候选边界，暂以本地文件和 Python CLI 为第一实现形态，不安装到全局 Codex。
- 将稳定角色实现为独立版本化角色合同、短提示词片段、输入/输出 Schema、工具与写入权限、停止条件、能力探针和交接协议。
- 只接入 Codex 工作区、Codex 会话上下文和本地命令/文件能力；不实现 Claude Code、Zcode、Qoder 或其他宿主适配。
- 实现项目意图路由、素材选择、项目/阶段/角色任务包、上下文预算、证据记录、确定性检查、修复循环和 Human Review Packet。
- 把用户可读的功能设计交付包固定为：使用方法、前端页面/元素/跳转、后端模块/接口/数据/错误/安全、性能/可维护性、测试设计、已知风险和用户决策。
- 以 T-0036 素材库为参考源，优先采用软件工程来源、案例、规范、模板和输出范式；提示词工程只作为 Agent 编排和评估参考。

## Non Goals

- 不安装或启用 Codex 全局 skill、MCP、plugin、automation、hook 或 AGENTS.md 行为。
- 不实现其他 Agent 宿主适配器，不进入真实业务项目，不部署、不处理生产数据、秘密、权限、支付、迁移或数据库变更。
- 不在一个超长提示词中塞入全部角色、全部素材和全部项目状态。
- 不把模型自报、评审 PASS 或命令成功直接当作生产级质量证明。

## Acceptance

- Codex 侧候选架构、状态机、角色边界、文件布局和调用协议有明确设计。
- 11 个稳定角色各有独立合同和短提示词层，至少包含固定立场、职责、禁止事项、输入、输出、工具、写入边界、停止条件、否决条件、能力探针和交接协议。
- 角色上下文、工具权限、写入路径、运行证据和独立评审上下文可机械区分；角色不能互相污染或自行批准。
- 阶段流程能从用户意图生成 P0-P12 的裁剪 Phase Profile、任务图和依赖；P1-P4 能生成非技术用户可读的功能/架构/详细设计包。
- 质量、安全、成本和可信度由内部检查器/角色/状态机承担；用户只处理目标、可见行为、重大取舍、剩余风险和阶段 Gate。
- T-0036 作为首个模拟/试运行输入，能够生成完整的素材选择、角色任务包、功能设计说明和 Human Review Packet。
- 每个实现切片有测试、验证证据和可回滚边界；实现不进入全局 Codex。

## Plan

1. 冻结 Codex-only 架构、状态机、文件协议和实现 Gate。
2. 实现最小 Core：项目/阶段/角色/工件/证据/Gate 数据模型与 Schema 检查。
3. 实现角色合同注册、短提示词组装、上下文隔离和权限/写入边界。
4. 实现意图路由、素材选择、Phase Profile、Task Graph 和 Work Packet。
5. 实现功能设计交付包、质量/安全/成本检查和修复/回归循环。
6. 用 T-0036 做端到端本地演练，独立评审后再考虑 Codex 全局接入 Gate。
