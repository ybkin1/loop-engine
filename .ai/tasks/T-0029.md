# T-0029: 执行层硬性化——角色隔离、否决链、输入冻结

## Status

`completed`


## 背景

用户指出当前 Loop Engine 的核心缺陷：角色结论无法变成真正的质量约束。同一 AI 既设计又实现又评审——"同一模型换名字"。

## 目标

将角色隔离、mini-Loop、否决机制从"提示词约定"升级为"硬性执行层"。

## 子任务

1. **重写 main-thread SKILL.md**：编排逻辑强制角色隔离（每次调用=独立Agent）、输入冻结（hash锁定）、否决链（BLOCKED不可覆盖）
2. **增强 validate_state.py**：新增自评自审检测、角色否决强制检查、输入版本一致性校验
3. **更新 independent-reviewer SKILL.md**：结构化否决输出格式（JSON，机器可解析）

## 硬性机制设计

| 机制 | 怎么硬性化 |
|------|-----------|
| 角色隔离 | main-thread 必须用 `Agent` tool；违规（直接执行）= validate_state.py 检测 |
| 否决链 | 角色输出结构化 JSON `{"verdict":"BLOCKED","findings":[...]}`；主控解析，不可覆盖 |
| 输入冻结 | task 文件记录 `input_hashes`；角色执行前后 hash 比对；变化 = BLOCKED |
| 自评自审阻断 | task 文件记录 `developer_agent_id` ≠ `reviewer_agent_id`；相同 = validate_state 报错 |

- 阶段: S6 → 架构增强
- 类型: implementation + design
