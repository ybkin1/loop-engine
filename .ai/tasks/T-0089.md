## 任务概述

StaffDeck 对标（T-0086 staffdeck-benchmark.md）U4/U7/U8/U9 落地：
- **U4 gate 决策反馈回路**：StaffDeck feedback/service.py 的"反馈归因 6 bucket + 技能健康度回流"模式 → loop-engine gate 拒绝/修复请求经验沉淀（可检索，改善 human_review_packet 与决策包质量）。
- **U7 evidence 可靠投递**：StaffDeck service_outbox.py 的"幂等键 + 条件领取 + 指数退避 + 卡死重置"模式 → `transactional_write_texts` 补幂等与重试。
- **U8 可观测性分层**：StaffDeck observability/ 的"事件/span/日志三层分离 + 异步队列不阻塞业务"模式 → guard 检查结果观测（耗时/频率/失败原因事件）。**观测异常不阻断业务；安全裁决仍 fail-closed**。
- **U9 生命周期**：StaffDeck scripts/dev.py 的"up/down/status + detach + pid + 健康轮询"模式 → scripts/ 生命周期脚本（AutoPlan 产品化前置）。

## 可验证验收标准

1. **[AC-01]** 反馈回路：gate 拒绝/修复请求经验沉淀有测试（记录结构化 + 可检索 + 含拒绝原因/修复建议）
2. **[AC-02]** evidence 幂等有测试（同内容重复提交不产生重复记录）；退避重试有测试（失败后按策略重试 + 上限）；卡死重置有测试
3. **[AC-03]** 观测事件落盘有测试（guard 检查耗时/频率/失败原因事件可查）；观测异常不阻断业务有测试（观测层抛错 → 业务继续，安全裁决不变）
4. **[AC-04]** 生命周期脚本有测试（up/down/status：pid 文件 + 健康轮询逻辑）
5. **[AC-05]** 全量测试通过无回归
6. **[AC-06]** 无约束被弱化（diff 审查证明；观测/反馈/投递增强均不得改变约束裁决语义）
