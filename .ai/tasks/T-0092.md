## 用户目标

1. eval 用例集 schema（输入/预期/评分规则 + 版本 + 分级）
2. eval 运行器（规则评分起步；LLM 判定可选、fail-safe 降级规则）
3. eval 报告（ReportBinding 风格落盘 .ai/evidence/observability/eval-report.json）
4. 与 guard/约束验证衔接（防护有效性评测）
5. 全量测试无回归

## 业务范围

- **IN SCOPE**:
  - `loop_core/evals.py`（或等效）：EvalCase schema（case_id/输入/预期/评分规则（规则式断言 或 LLM 判定）/severity/版本）、EvalRunner（执行用例 → 评分 → 汇总）、EvalReport（ReportBinding 风格：pass/fail/skip + 明细 + 时间戳 + git_commit）
  - 规则评分器（断言类型：text_contains/text_matches/json_equals/exit_code 等）；LLM 判定可选（复用 D1 层 ProtocolDriver；不可用 → SKIPPED 不阻断）
  - 内置样例用例集（针对 guard 防护：如"越界写入被拦"等正/负样例，与 guard_health 对照电池衔接）
  - 配套测试 + 全量回归

- **OUT OF SCOPE**:
  - 真实模型评测（eval 运行器可离线规则模式运行；LLM 判定仅可选增强）
  - 部署、回滚、数据库迁移、生产权限修改、生产数据处理
  - 真实密钥处理
  - **不得弱化任何已激活约束**

## 可验证验收标准

1. **[AC-01]** eval schema：EvalCase 字段完整（case_id/输入/预期/评分规则/severity/版本）+ schema 校验（非法用例拒绝）
2. **[AC-02]** 运行器：规则评分（≥3 种断言类型有测试）；LLM 判定可选（不可用 → SKIPPED 不阻断）；异常隔离（单用例失败不影响其余）
3. **[AC-03]** eval 报告：ReportBinding 风格落盘（pass/fail/skip 统计 + 明细 + git_commit + 时间戳）
4. **[AC-04]** 内置样例集：≥4 个 guard 防护正/负样例（与 guard_health 衔接）
5. **[AC-05]** 全量测试通过无回归
6. **[AC-06]** 无约束被弱化（diff 审查）；测试隔离（LLM 全 mock）
