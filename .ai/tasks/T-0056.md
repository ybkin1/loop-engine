# T-0056: Loop 工程质量保障层改造

## Status

`completed`

## Phase

S6-delivery

## Objective

消除当前 Loop 工程"质量保障全靠 AI 自觉"的架构缺陷，将内容质量从"知识层指导"升级为"执行层强制"——机器拦截 + 独立审查 + 证据链防伪造。

## Root Cause

架构设计把"质量保障"分配给了 AI 自律层（知识层），而没有为执行层设计任何可机验的内容质量校验机制。`_simulate_role_output()` 制造假的 PASS 输出，系统无法分辨真假。

## Scope

### P0：机器拦截层
- 新建 `hooks/scripts/content_guard.py` — PreToolUse hook，拦截 Write/Edit 操作
- 编码规范检查（ruff）、禁止硬编码密钥、架构合规检查
- 注册到 `hooks/hooks.json`

### P0：消除 simulate 生产路径
- `executor.py`: `_launch_agent_subprocess()` — 无 run.py 时直接抛 AgentUnavailableError
- `_simulate_role_output()` — 保留仅测试用，标注 TEST ONLY

### P1：强制 Agent 审查门禁
- `gate_guard.py`: 验证独立审查证据（reviewer_session_id ≠ developer_session_id）
- `gates.yaml`: gate 定义新增 `content_quality` 字段

### P1：test-engineer SKILL.md 补全
- 从 5 行骨架扩展为 ~150 行生产级代理提示词

### P1：证据链防伪造
- `executor.py` `validate_step()`: 验证 reviewer_session_id、input_files_sha256、timestamp

### P2：设计文档强制引用 + CODING_STANDARDS 补全
- `content_guard.py`: gate content_quality.architecture_compliance → 校验模块结构
- `.ai/CODING_STANDARDS.md`: 从 3 句话扩展为完整编码规范

## Required Gates

- G-T-0056-CONTENT-QUALITY-ENFORCEMENT

## Forbidden Actions

- 修改 AGENTS.md
- 进入、创建或修改真实业务项目
- deploy / rollback / database / permission / secret / payment / production_data / migration
- 以 reviewer PASS、validator、测试或 AI 建议替代用户批准
- 在 pending gate 下继续执行后续阶段

## Acceptance Criteria

1. `content_guard.py` Hook 能拦截不符合 PEP 8 的代码写入
2. 模拟输出不再在生产路径中生成
3. 独立审查报告缺少会话 ID 时 gate 被阻断
4. `test-engineer` SKILL.md 达到与 `quality-engineer` 同等完整度
5. `validate_step()` 能检测伪造的审查证据
6. 全量回归测试通过
7. `validate_state.py` 通过
