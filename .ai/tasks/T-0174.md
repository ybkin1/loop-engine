# T-0174: hooks 不接管根因定位与修复 — loop-governance 插件登记进 ZCode 市场清单

## 任务概述

KNOWN_ISSUES 的 hooks-not-loaded Critical 长期记录"ZCode 平台忽略项目 hooks，
需平台侧修复，仓库内无法解决"。用户质疑（2026-08-10）"在 zcode 侧是无法
修复了么"，本任务逆向调查 ZCode 实际加载源码，定位并修复真实根因。

**调查结论（逆向 `C:\Program Files\ZCode\resources\glm\zcode.cjs`）**：
- 插件发现 `scanOfficialCache`：优先读 `bundled-marketplace.json` 的
  manifest.plugins 清单（lGr）；**清单非空时短路，不扫描文件系统**
- bundled-marketplace.json 有 7 个官方插件（android-emulator/browser-use/
  document-skills/ios-simulator/restore-legacy-sessions/skill-creator/
  zcode-guide），**没有 loop-governance**（手工部署的缓存插件，从未登记）
- → loop-governance 永远不被发现 → hookCount 0、loop-tools MCP 不加载
- browser-use 等内置插件走 officialPluginRoots（resources/glm/packages），
  所以正常生效——平台本身支持插件 hooks
- 平台支持的 hook 事件集：SessionStart/UserPromptSubmit/PreToolUse/
  PermissionRequest/PostToolUse/PostToolUseFailure/Stop（我们的 hooks.json
  用的 SessionStart/PreToolUse 均在支持集合）
- 项目级 `.zcode/config.json` 的 hooks 键 → 恒定诊断 config_project_hooks_ignored
  （平台不支持项目级 hooks 事件注册；插件 hooks 是正路，该警告可忽略）

来源：用户指令（2026-08-10）"hooks 复查：问题仍存在——这个在zcode侧是
无法修复了么？"
