# Task T-0036: 建立软件工程与提示词工程素材库基线

## User Outcome

建立一个可追溯、可检索、可组合的候选素材库，为后续 Loop 角色合同、阶段模板、质量门禁、提示词和运行时约束提供外部工程知识基线。素材库不能把来源材料直接冒充为 Loop 规则，也不能把一次性 AI 生成结果当作工程标准。

## Scope

- 联网检索提示词工程、LLM Agent、评估、软件生命周期、需求、架构、API、编码、测试、安全、交付、运维和项目管理资料。
- 优先记录官方标准、官方规范、官方文档和可执行工具；同时单独标记方法论、模板、研究论文和 Loop 自定义适配。
- 为每条素材记录来源、版本/日期、适用条件、禁用条件、输入、输出、模板/Schema、风险和证据等级。
- 建立主题覆盖矩阵、来源核验记录、标准化文档模板和组合规则。
- 整理软件工程模板、规范、案例、用例和输出范式，并明确材料类别和证据等级。
- 记录适用场景、风险、禁止误用和选用规则；执行覆盖缺口与重复内容检查。
- 生成面向用户的素材库评审包，区分已完成、未覆盖、待复核和需要用户决定的内容。
- 明确“检索候选素材 -> 选择组合 -> 形成项目配置 -> 用户 Gate -> 执行”的边界。

## Non Goals

- 不实现 Loop Core、Loop Runtime、Host Adapter 或任何新的 Agent 编排行为。
- 不安装或启用 skill、MCP、agent、automation、protocol、plugin、hook。
- 不把本任务的素材库直接升级为已批准的项目规则；不进入外部业务项目。
- 不复制受版权保护的规范正文；只保存来源元数据、短摘要和 Loop 适配说明。

## Acceptance

- 素材库覆盖提示词/Agent 与主要软件工程生命周期域，并明确覆盖边界和未覆盖项。
- 每条素材具备统一元数据：`material_id`、`category`、`title`、`source_url`、`source_type`、`authority`、`version_or_date`、`problem_solved`、`when_to_use`、`when_not_to_use`、`inputs`、`outputs`、`template_or_schema`、`adaptation_notes`、`risks`、`evidence_level`。
- 区分原始标准/官方规范、权威工程实践、方法论、模板、可执行工具、AI/Agent 专门实践和 Loop 适配层。
- 记录联网核验时间、HTTP/最终 URL、页面标题和不可访问来源，不把失败访问当作已核实。
- 提供至少需求、架构、详细设计、API、测试、编码评审、安全、发布和人工评审包模板。
- 记录成本、上下文预算、复用和返工控制原则，但不承诺未经测量的 token 节省效果。
- 软件工程素材、提示词/Agent 素材、Loop 适配层和输出模板之间的分级、适用边界、禁止误用和选用规则可被用户读懂。
- 覆盖缺口和重复内容有独立检查记录；用户可读评审包明确候选边界，候选基线接受由独立用户决策证据记录。
- `validate_state.py`、素材库结构检查和 `git diff --check` 通过。

## Plan

1. 建立来源登记、分类体系和材料元数据 schema。
2. 联网核验一手来源，并记录状态、版本/日期和适用边界。
3. 编写 Loop 可组合的模板骨架和领域覆盖矩阵。
4. 完成覆盖/重复检查和用户可读素材库评审包。
5. 对 T-0036 执行独立评审、必要修复和独立复审。
6. 由用户决定是否接受 T-0036 作为 Codex Loop 候选素材基线；冻结版本后才允许 T-0037 独立评审。
