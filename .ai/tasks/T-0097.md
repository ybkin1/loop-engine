## 用户目标

1. incident 记录：事故/失败事件（类别/影响/时间线/处置）结构化落盘 + 检索
2. 复盘：与 incident 关联（根因分析 + 行动项 owner/deadline）+ 状态跟踪（open/closed）
3. second-failure 检测：同类复发识别 → 生成任务建议（report 级，不自动登记 task_graph）+ 阻断语义（直到有 owner 行动项）
4. 与 gate_lessons/SLO 门禁衔接（失败事件来源统一）
5. 全量测试无回归

## 业务范围

- **IN SCOPE**:
  - `loop_core/incidents.py`（或等效）：IncidentRecord schema（incident_id/类别（gate_rejection/guard_failure/regression/slo_breach/other）/影响（severity + 范围）/时间线/处置/状态/来源）+ 落盘（.ai/evidence/observability/incidents.yaml 或 JSONL）+ 检索
  - `loop_core/retrospectives.py`（或等效）：Retrospective schema（关联 incident_id/根因分析/行动项列表（action_item: owner/deadline/status）/状态）+ 落盘 + 状态跟踪
  - **second-failure 检测**：`detect_second_failure(incidents)` —— 同类别 + 同根因指纹复发 → SecondFailureRecord（第一次 incident_id/复发 incident_id/建议任务草稿（标题/范围/原因））→ **report 级**（.ai/evidence/observability/second-failures.yaml）+ 阻断语义：`second_failure_block(project_root)` —— 存在未解决 second-failure（无 owner 行动项）→ BLOCK（fail-closed；可豁免记录）
  - 与 gate_lessons 衔接：gate 拒绝次数可作为 incident 来源（自动登记或引用）
  - 配套测试 + 全量回归

- **OUT OF SCOPE**:
  - 自动登记 task_graph 任务（second-failure 仅生成任务建议草稿，登记需用户 gate 批准）
  - 部署、回滚、数据库迁移、生产权限修改、生产数据处理
  - **不得弱化任何已激活约束**（本任务新增检测为强化方向）

## 可验证验收标准

1. **[AC-01]** incident 记录：schema 完整 + 落盘 + 检索（by_category/by_status/keyword 有测试）
2. **[AC-02]** 复盘：关联 incident + 行动项（owner/deadline/status）+ 状态跟踪（open→closed 有测试）
3. **[AC-03]** second-failure 检测：同类复发识别（同类别 + 同根因指纹）→ 建议草稿生成（有测试）；未解决（无 owner 行动项）→ 阻断（fail-closed，有测试）；有 owner 行动项 → 放行；豁免记录生效
4. **[AC-04]** 与 gate_lessons 衔接：gate 拒绝可登记为 incident 来源（有测试）
5. **[AC-05]** 全量测试通过无回归
6. **[AC-06]** 无约束被弱化（diff 审查；新增检测为强化方向；不自动登记任务）
