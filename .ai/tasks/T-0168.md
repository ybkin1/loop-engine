# T-0168: OQA-5D 扩展 — AUTHENTICITY 真实性维度（AI 行为验证）

## 任务概述

OQA-4D（T-0167）已覆盖"产物形态验证"（需求符合性/编码规范/设计理念/
软件工程）。但 AI 产出的最大风险是**行为真实性**：幻觉（引用不存在的
模块/API）、编造（声称做了实际没做、伪造证据）、偷懒（占位符/空实现/
浅测试）、过度设计（幽灵接口/死代码）、前后偏差（文档/接口/状态与实现
漂移）。本任务新增第五维 **AUTHENTICITY 真实性**，10 个机器可执行检查器，
让 loop 工程质量验证从"形状对不对"升级为"东西是不是真的"。

来源：用户指令（2026-08-10）"loop工程要解决的就是避免90%里面没有屎…
防止AI幻觉、偷懒、自己编造，保证AI的产出符合实际软件工程项目的质量要求"。
用户批准 OQA-5D 扩展方案（含 AL-02 阈值：断言数≥1 + 必须有失败路径用例）。

## 业务范围（AUTHENTICITY 维度 10 检查器）

1. **AH-01 引用存在性**（幻觉/BLOCKER）：import/require 目标必须存在；
   调用的 API 符号必须在依赖声明中（对齐 import-guard 语义）
2. **AH-02 文件引用存在性**（幻觉/BLOCKER）：文档/代码引用的相对路径必须存在
3. **AF-01 证据真实性**（编造/BLOCKER）：quality_report/evidence 的
   content_hash 与真实文件一致；exit_code=0 必须有对应产物
4. **AF-02 完成声明真实性**（编造/BLOCKER）：state 声称 completed 的任务，
   其 AC 产物必须全部存在
5. **AL-01 占位符检测**（偷懒/BLOCKER）：TODO/FIXME/stub/NotImplemented/
   空函数体/直接 return null
6. **AL-02 测试质量**（偷懒/WARNING）：测试断言数≥1、必须有失败路径用例、
   禁止空测试（用户已批准阈值）
7. **AO-01 死代码检测**（过度设计/WARNING）：导出符号零引用（跨文件引用计数）
8. **AO-02 幽灵接口检测**（过度设计/WARNING）：接口/抽象类无实现，
   或实现了无调用方
9. **AI-01 文档-实现漂移**（前后偏差/WARNING）：文档声明签名 vs 实际签名
10. **AI-02 状态-产物漂移**（前后偏差/WARNING）：state.yaml 任务状态 vs
    .ai/evidence 产物存在性
