# T-0054: MCP Agent Runtime — 三层代理模型的 MCP 替代方案

## Status

`in_progress`

## Phase

S6-delivery

## Objective

利用 ZCode MCP 协议实现独立 Agent 运行时，绕过"子代理无 Agent 工具"限制，使 Loop 工程在 ZCode 上实现全自动三层代理编排。

不修改 ZCode、不依赖第三方工具、不绕过 Loop 治理。

## 架构设计

```
ZCode 会话（hooks 保护层）
  │
  ├─ MCP 工具调用: loop_dispatch(manifest)
  │     │
  │     ▼
  │  ┌─ MCP Agent Runtime（独立进程，纯计算）───────────────┐
  │  │                                                       │
  │  │  for each subagent in manifest:                       │
  │  │    1. 加载角色 SKILL.md                               │
  │  │    2. HTTP POST → DeepSeek/Claude API                 │
  │  │    3. 接收纯文本输出                                   │
  │  │    4. 校验 INPUT_HASH（自实现）                       │
  │  │    5. 失败 → 重试（最多 N 次）                       │
  │  │                                                       │
  │  │  返回: 结构化 SubagentResult[]                         │
  │  └───────────────────────────────────────────────────────┘
  │     │
  │     ▼ 返回纯文本（无文件写入）
  │
  ├─ ZCode 写 evidence + 调 main-thread 汇总（过 hooks）
  └─ 呈现 gate
```

**安全边界：MCP Runtime 只管"想"（调 LLM），不管"写"（文件操作）。所有文件写入仍在 ZCode 会话中，受 hooks 保护。**

## 实现组件

### 1. `tools/mcp_agent_runtime.py`（核心）
- `MCPAgentRuntime` 类
- `dispatch_manifest(manifest)` → 返回 SubagentResult 列表
- 从环境变量读取 API key
- 纯 HTTP 调用，不 import ZCode 任何模块

### 2. `tools/server.py`（MCP 工具注册）
- 新增工具 `loop_dispatch_agents`
- 输入：SubagentManifest JSON
- 输出：聚合结果 JSON

### 3. 角色 Skill 加载
- `agents/{role}/SKILL.md` → system prompt
- `agents/{role}/references/` → additional context
- 按 manifest 中的 role_hint 自动匹配

### 4. 文件写入委托
- MCP Runtime 返回的文本中如包含文件写入意图
- ZCode 会话解析并执行 Write 工具调用
- 确保 hooks 拦截生效

## 风险与规避

| 风险 | 规避 |
|------|------|
| MCP Runtime 绕过 hooks 写文件 | Runtime **不 import Write/Edit/Bash**，只调 HTTP API；返回纯文本 |
| API key 泄露 | 从环境变量读取，不硬编码 |
| Token 成本不可控 | 每 subagent 单独计 token，预算上限可配 |
| LLM 幻觉（假结果） | INPUT_HASH 校验 + ZCode 侧 evidence 验证 |
| MCP 进程崩溃 | 超时 + ZCode 侧 fallback 到手动调度 |
