# Task T-0035: 优化 Loop 工程系统设计提案 v0.2

## User Outcome

得到一份比 `v0.1` 更明确、可实现、可验证、可跨宿主扩展的 Loop 工程系统设计提案，准确表达用户对生产级 AI 软件交付的要求。

## Scope

- 读取附件内容和原 `v0.1` 设计意图。
- 重构产品身份、独立工具/外部 Agent 形态、Core/Runtime/Adapter 架构。
- 明确意图识别、项目分级、硬约束、证据可信度和 enforcement level。
- 明确角色合同、角色能力、角色 Loop、阶段 Loop、阶段 Gate 和 Human Review Packet。
- 具体定义角色能力的运行前 admission、运行中验证、运行后效果验证和失效降级。
- 明确认可 P0-P12 为稳定宏阶段，并定义 `Phase Profile` 的合并、展开和 `NOT_APPLICABLE` 规则。
- 为 Human Review Packet 增加通用模板和各阶段用户决策问题。
- 补齐 Quality Profile、评审修复、跨会话长期文档、成本和实施路线。
- 新建 `docs/loop-engineering-system-design.proposed.v0.2.md`，保留历史版本不覆盖。

## Non Goals

- 不实现 Loop Runtime、Host Adapter 或新的 Agent 编排。
- 不修改全局 Project Governor、`AGENTS.md` 或宿主配置。
- 不安装或启用 skill、MCP、agent、automation、protocol、plugin、hook 或 runtime。
- 不部署、不进入外部业务项目、不处理生产数据、秘密、权限、支付或迁移。

## Acceptance

- v0.2 明确 `loop-engineering-lab` 本身是 Loop 产品的真实开发项目。
- 文档区分 Loop Core、Loop Runtime 和 Host Adapter，并声明宿主 enforcement level。
- 文档定义项目分级、硬性阻断、角色合同、角色/阶段 Loop 和人工 Gate。
- 文档定义确定性质量、证据 lineage、freshness、独立评审和修复回归。
- 文档明确跨会话依赖长期项目文档和机器状态，HANDOFF 仅为索引。
- 文档包含成本/返工原则、风险对策、Definition of Done 和分阶段路线。
- 文档不把提案内容冒充为已实现能力。

## Plan

1. 读取附件和历史设计输入。
2. 形成 v0.2 结构和内容重构。
3. 记录优化证据和版本关系。
4. 执行文档结构、敏感表述和项目状态校验。
