# 角色专属参考文档 (Role References)

> 对齐 ZCode agents/references/ 设计。
> 每个角色在执行工作时参照的专业标准。

---

## R01 产品经理 — 需求检查清单

### 需求质量标准
- [ ] 每条需求有唯一 ID（REQ-001, REQ-002...）
- [ ] 每条需求有明确的验收标准（可测量、可验证）
- [ ] 需求间无矛盾
- [ ] 优先级排序有依据（RICE/MoSCoW）
- [ ] 非功能需求已识别（性能/安全/可用性）
- [ ] 用户画像已定义
- [ ] 边界条件已说明（不做什么）

### 验收标准模板
```
REQ-{ID}: {需求标题}
  描述: {一句话描述}
  验收标准:
    - AC1: {可测量的条件}
    - AC2: {可测量的条件}
  优先级: MUST / SHOULD / COULD / WON'T
  依赖: {前置需求ID}
```

## R04 系统架构师 — 架构检查清单

### 14 项架构交付物
1. [ ] 系统上下文图（C4 Level 1）
2. [ ] 容器图（C4 Level 2）
3. [ ] 模块划分与职责
4. [ ] 模块间依赖图（有向无环）
5. [ ] 接口契约定义
6. [ ] 数据模型
7. [ ] 错误处理策略
8. [ ] 安全边界定义
9. [ ] 非功能需求（性能/可用性/可扩展性）
10. [ ] 技术选型与理由（ADR）
11. [ ] 部署架构
12. [ ] 监控策略
13. [ ] 回滚策略
14. [ ] 约束与假设

### 架构审查标准
- [ ] 无循环依赖
- [ ] 每个模块职责单一
- [ ] 接口契约覆盖所有模块间通信
- [ ] 依赖方向单向（上层→下层）
- [ ] 安全边界明确（信任域划分）

### 缺陷分级
| 级别 | 定义 | 处理 |
|------|------|------|
| P0 | 系统崩溃/数据丢失/安全漏洞 | **阻止交付**，立即修复 |
| P1 | 核心功能不可用 | **阻止交付**，本迭代修复 |
| P2 | 非核心功能异常 | 记录，下迭代修复 |
| P3 | 体验问题/建议 | 记录，按优先级排期 |

## R08 安全工程师 — 安全检查清单

### 安全扫描项
- [ ] 无硬编码密钥/密码/token
- [ ] 无 SQL 注入面
- [ ] 无 XSS 注入面
- [ ] 无路径遍历
- [ ] 无命令注入
- [ ] 依赖无已知 CVE（HIGH/CRITICAL）
- [ ] 权限最小化
- [ ] 输入验证完整
- [ ] 错误信息不泄露内部细节
- [ ] 日志不记录敏感数据

### 安全否决标准
- **CRITICAL**: 远程代码执行、认证绕过、数据泄露 → 立即阻止
- **HIGH**: SQL注入、XSS、权限提升 → 阻止交付
- **MEDIUM**: CSRF、信息泄露 → 记录，限期修复
- **LOW**: 配置建议 → 记录

## R09 独立评审员 — 评审检查清单

### 六维评审
| 维度 | 检查项 |
|------|--------|
| 正确性 | 逻辑是否正确？边界条件是否处理？ |
| 可读性 | 命名是否清晰？注释是否充分？ |
| 架构 | 是否符合架构设计？是否越界？ |
| 安全 | 是否有注入面？是否泄露敏感信息？ |
| 性能 | 是否有N+1查询？是否有内存泄漏？ |
| 测试 | 测试是否覆盖核心路径？边界是否测试？ |

### 评审判定标准
- **PASS**: P0=0, P1=0, 所有维度无高危
- **FAIL**: 存在 P0 或 P1 → 打回修复
- **BLOCKED**: 架构级问题 → 升级 R04
