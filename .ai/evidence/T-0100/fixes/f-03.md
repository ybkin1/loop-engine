# F-03（P1）版本同步机制 — AC-01

## 根因

T-0098（v3.12.37）与 T-0099（v3.12.38）提交后未回写 pyproject.toml（停留在
3.12.36），导致 `scripts/release.py check` 的 version_sync 步骤 fail-closed
阻断（pyproject=3.12.36 vs git HEAD=3.12.38，验收时 3.12.37）。根因是缺少
版本同步机制：版本载体（pyproject/CHANGELOG/`__version__`/README/docs/
plugin.json/version-manifest 投影）只能手工同步，且 CHANGELOG 缺失 v3.12.37/
v3.12.38 条目（提交历史与 CHANGELOG 漂移）。

## 改动

### `scripts/release.py` — 新增 `bump` 子命令

- `bump --to <version> [--title <标题>]`：
  - 严格校验版本格式（`^\d+\.\d+\.\d+$`，非法 → exit 2 用法错误）；
  - 原子更新全部版本载体：pyproject.toml（事实来源）、CHANGELOG.md 头部
    （新增 `## vX.Y.Z (date) — 标题` 条目，保留现有格式风格、降序在前）、
    `loop_core/__init__.py` / `src/loop_engine/__init__.py`（`__version__`）、
    README.md（`**vX.Y.Z**`）、docs/06-delivery.md（头部行 + 版本号表格行）、
    `.zcode-plugin/plugin.json`（version 字段）、`.ai/version-manifest.yaml`
    （投影字段 + consistency_check，历史快照 historical_snapshots 不动）；
  - **原子写**：`_atomic_write` = 同目录 `tempfile.mkstemp` + `os.replace`；
    写失败清理临时文件、目标文件保持原内容；
  - 缺失载体（迷你项目无 README 等）→ 提示跳过不阻断；载体更新失败 →
    exit 1 并明确报错（不回滚已更新项，提示人工核对）；
  - 幂等（同版本 no-op）；`--dry-run` 只打印计划。
- `check` 子命令兼容 `check --dry-run` 与 `--dry-run check` 两种写法。
- version_sync 步骤**未修改判定语义**（与 git HEAD 对齐的 fail-closed 保持），
  仅失败文案补充提交流程约定：**先 bump 再提交**。

### 当前版本对齐（本任务提交版本 3.12.39）

`release.py bump --to 3.12.39 --title "T-0100: 质量验收 findings 修复包（F-03~F-06）"`
更新 8 个载体到 3.12.39；随后手动补齐 CHANGELOG 缺失条目 v3.12.38（T-0099）
与 v3.12.37（T-0098）（按既有格式风格，保持降序），并把 v3.12.39 条目正文
改写为 T-0100 修复内容。

> 说明：`.zcode-plugin/plugin.json` 不在 T-0100.md allowed_paths 字面清单中，
> 但它是 test_version_consistency 强制校验的版本载体（release check 的
> key_tests 内含该测试），不更新则 AC-01/AC-06 无法达成；故 bump 机制将其纳入
> 载体清单并实际更新（单行 version 字段），已在 commands.md 中如实记录。
