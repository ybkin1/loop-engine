# F-06（P3）安全扫描误报白名单 — AC-05

## 根因

`agents/security-engineer/scripts/run_security_scan.py` 注入/密钥扫描无
自排除与白名单：命中自身正则规则表（security_scan.py:42-47 等）、测试夹具
（tests/test_*.py）、seeded_defects 故意缺陷样本、文档示例（agents/
references/*.md）、`yaml.load(..., Loader=UniqueKeyLoader)`（SafeLoader 子类，
安全）；外加两条粗规则误报（UI 标签 `[loop-update]` 被 `\bUPDATE\b` 当 SQL、
字符串字面量 `"innerHTML XSS"` 当 HTML 绑定）。T-0099 实测 26 HIGH + 7 secret
全为误报 → verdict BLOCKED 由设计所致。

## 改动

`agents/security-engineer/scripts/run_security_scan.py`：

1. **路径白名单（已验证类别，真实代码路径不豁免）** `_path_whitelist_category`：
   - `scanner_self`：扫描器自身规则表文件（scripts/security_scan.py、
     agents/security-engineer/scripts/run_security_scan.py、
     tools/tool_security_scan.py、loop_core/security_scanner.py）；
   - `test_fixture`：`tests/` 下测试夹具 + `tests/seeded_defects/` 故意缺陷样本
     （含 fixture/fixtures 目录名）；
   - `docs`：`docs/` 目录 + `agents/references/` 文档（.md/.rst/.txt）；
   - `archive`：`archive/` 归档非生产代码（与遗留 security_scan.py 排除一致）。
   白名单跳过以 `skipped_files`（posix 路径 + 类别）透明返回，供复核。
2. **SafeLoader 子类识别** `_is_safe_loader_call`：`yaml.load(..., Loader=X)`
   若 X 直接是 yaml.SafeLoader 或同文件定义、基类含 SafeLoader 的类
   （`class UniqueKeyLoader(yaml.SafeLoader)`）→ 不报；无 Loader 或非安全
   Loader 照常报。
3. **占位符排除**：EXCLUDE_PATTERNS 增加 `{...}` 占位符、changeme/dummy/
   sample/fake、test_key 等模式（修复 certification_runner.py:686
   `pwd='{password}'` 类误报；与既有行级排除机制一致）。
4. **规则精度修正**（同属误报清零，真实 SQL/HTML 仍命中）：
   - SQL 关键字改为语句上下文形态 `_SQL_STMT`（SELECT…FROM / INSERT INTO /
     UPDATE…SET / DELETE FROM / DROP TABLE…），`[loop-update]` 等 UI 标签不再
     命中；三条 SQL 规则（f-string/+ /%）与 raw SQL execute 共用；
   - `unsafe HTML binding` 加字符串字面量 lookaround，`"innerHTML XSS"`
     描述文本不再命中（真实 `el.innerHTML = x` 仍报）。

## P2 追加修复（独立审查条件，2026-08-02）

独立审查（.ai/evidence/T-0100/review/independent-review.md 3.3）指出 F-06 的
两条规则精度修正造成两处检测覆盖回退（旧规则检出、新规则静默），按
CONDITIONAL_GO 条件修复：

### P2-1：split-literal SQL 拼接恢复 HIGH 检出

- 回退现场：`"SELECT " + cols + " FROM " + tbl + " WHERE id=" + uid` ——
  旧 `+` 规则（HIGH 阻断级）命中，新 `_SQL_STMT` 语句上下文规则要求关键词
  同处一个字面量，对此形态漏检。
- 修复：HIGH_RISK_PATTERNS 追加规则 `SQL concatenation (split literal)`
  （独立规则，不改动既有 f-string/+ /% /raw SQL execute 规则，零弱化）。
  正则（独立审查已验证零误报于 UI 标签）：
  ```
  ["']\s*(?:SELECT|INSERT\s+INTO|UPDATE|DELETE\s+FROM|DROP\s+(?:TABLE|DATABASE|INDEX|SCHEMA|VIEW))\s+[^"']*["']\s*[+%]
  ```
  （re.IGNORECASE；仅命中"字面量起始即 SQL 关键词 + 拼接/格式化运算符"，
  `"SELECT color"` 等无运算符 UI 标签不命中）→ 命中即 HIGH 阻断级。

### P2-2：bracket-access HTML sink 恢复 MEDIUM 检出

- 回退现场：`obj["innerHTML"] = userInput` —— 旧 MEDIUM 规则命中，
  新 `(?<!["'])…(?!["'])` lookaround 将其排除（关键词在引号内）。
- 修复：`unsafe HTML binding` 规则追加 bracket-access 分支（OR 联合，
  既有 lookaround 分支原样保留）。正则（独立审查已验证 `"innerHTML XSS"`
  描述文本与只读索引访问均不误报）：
  ```
  \.(?:innerHTML|outerHTML|insertAdjacentHTML)\s*=|\[["'](?:innerHTML|outerHTML|insertAdjacentHTML)["']\]\s*=
  ```
  分支以 `\s*=` 结尾只命中"赋值"形态 → MEDIUM；`x = obj["innerHTML"]`
  只读访问与 `el.innerHTML = x` 直接赋值语义均不变。
