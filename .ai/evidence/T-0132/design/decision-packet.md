# D-04: 决策包（T-0132 三层质量线程架构）

> T-0132 设计文档 · 2026-08-07 · 交用户裁决

## 1. 方案摘要（一句话）

把 loop 从"阶段终点质量门禁"升级为**三层质量线程架构**：质量类 agent 独立线程
对每个动作产出做多轮校验，判定层复用 eval 栈（机器可复算），配防伪造五项机制
（D-02）与防锁死三级恢复（D-03）。

## 2. 四个设计产出

| 文档 | 内容 | 核心结论 |
|---|---|---|
| D-01 三层模型 | 角色分组契约 / quality_pair schema / 分层伴飞 / 轮次协议 / eval 核心校验 | 质量线程结构性独立于执行线程；eval 规则断言 = 最终证据层 |
| D-02 防伪造 | M1 机器可复算 / M2 不见预期 / M3 哈希先行 / M4 抽查复算 / M5 引用证据 | agent 的话永远不是最终证据，eval 复算才是 |
| D-03 防锁死 | L1 修复器 / L2 快照回滚 / L3 手工接管 + 回滚三原则 + 心跳 + 恢复演练 | 现有 --repair/repair_continuity 已实测可用；回滚快照先行、evidence 不丢 |

## 5. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| eval 桥接不完整（agent 判定无法断言化） | MEDIUM | L2 判定仅建议层，断言化失败则该判定不进入报告（fail-safe） |
| 校验密度推高 token/时间成本 | MEDIUM | 分层伴飞（轻量动作 hook 化，仅 ~20% 动作上 agent 线程） |
| 恢复路径与现有工具冲突 | LOW | 演练先行（E1~E5 通过才授权自治） |
| 改动面大（6 角色契约 + 4 内核文件） | MEDIUM | 分阶段落地 + 每阶段独立审查；hooks/ 改动仅 P3 明确授权项 |

## 6. 待用户裁决（选择题）

**Q1 落地节奏**：
- A（推荐）：按 P0→P4 分阶段，每阶段一个任务一个 gate——改动面可控，每阶段你可验收
- B：P3+P4 合并为一个任务——快但改动面大
- C：暂不落地，本设计归档

**Q2 质量校验密度**：
- A（推荐）：D-01 §4.1 分层伴飞（轻量 hook / 重量 agent，~20% 动作上线程）
- B：所有动作都上质量线程（更严，成本显著上升）
- C：维持现状（阶段门禁）

**Q3 抽查复算比例 recompute_rate**：
- A（推荐）：0.1（10% 报告被机器抽样复算）
- B：0.2（更严）
- C：0.05（更省）

**Q4 轮次上限**：
- A（推荐）：3 轮后 ESCALATE（默认不通过：缩小范围或回滚重做）
- B：5 轮（给更多修复机会）
- C：2 轮（更快失败）

## 7. 建议

按 Q1-A + Q2-A + Q3-A + Q4-A 组合推进：先 P0 状态硬化（顺带解决当前
"治理文件每次变更都要手工 repair"的高频摩擦），再依次 P1→P4。每阶段
独立 gate、独立审查，你只需在每个阶段结束时看结论包做一次选择题。

**残余风险诚实标注**：任何机制都无法消除"同一主体同时破坏全部防线"的
理论风险（D-02 §4 末行）——这是 AI 治理的固有边界，由你的最终验收兜底；
本设计做到的是：让伪造与锁死的**可操作成本**高到实践中不可行。
