## 1. 方法

### 1.1 研究问题与单一变量

任务启动时向 AI 注入"开工前盲点自检"提示词（D-03 设计-1 §1.3.1 候选文本），是否显著提升任务开工产出（盲点清单 + 执行前声明）质量？

- **实验组 A**：任务提示词 = 任务卡文本 + 盲点自检提示词（注入文本固化于 `prompts/blindspot-injection-v1.md`，版本 v1）
- **对照组 B**：任务提示词 = 任务卡文本（现状，无盲点自检提示词）

两组除注入文本外完全一致：同一任务卡文本、同一输出约束（开工产出：执行前声明；A 组另含盲点清单表格，格式由注入文本规定）。

### 1.2 执行路径声明（降级方案）

**本实验采用 D-04 降级路径（规则式模拟/构造性评估），未触发任何 LLM 外部调用**（硬约束：禁止外部 API 调用）：

- 产出**生成**：按两组策略模型**构造**（10 份实验产出 + 2 份校准样例，由执行代理按 A/B 策略规范撰写）——B 组忠实于"无盲点自检提示词"的现状行为（任务卡四要素 + 执行前声明，不系统枚举隐藏变量）；A 组遵循注入文本的填写规则（≥3 条盲点、每条含后果与确认标记）。
- 产出**评分**：100% 复用现有 eval 栈自动化（`loop_core.evals`：EvalCase schema 校验 → EvalRunner 规则断言 → EvalReport ReportBinding 报告；另用 `tools/tool_eval.py` CLI 复跑同一 case 集验证 CLI 路径一致）。
- **统计检验**：Mann-Whitney U 精确检验（穷举）、Fisher 精确检验、Cohen's d（纯 Python 实现，无 scipy 依赖），脚本 `run_experiment.py` 可复跑。
- **结论效力边界**：本实验验证的是（a）评分管线与 case 集（含校准）可用、（b）模拟数据与设计假设一致；**真实模型效应需路径 A（API）或路径 B（真实会话）用同一 case 集复跑**。下文信号判定为"模拟一致 + 管线验证"层级。

### 1.3 实验对象与规模

- 场景：S1 需求澄清 / S2 架构设计 / S4 实现任务 / S5 安全审查 / S6 交付检查（对应 loop 五个强制人工评审阶段；D-04 §3）
- 规模：5 场景 × 2 组 × 1 次 = **10 份实验产出**（比 D-04 最小可行 18 份更轻，探索性；统计仅作参考）+ 2 份校准样例（1 高 1 低）
- 评分单元：每份产出 8 个 EvalCase（1 结构 + 5 种子命中 + 1 后果说明 + 1 确认标记）→ **96 个 case**，tags 标 `experiment:blindspot`、`group:A/B`、`scenario:S*`、`dimension:D*`
- 校准（D-04 §5 评分纪律）：calib-high（5/5 种子 + 后果 + 确认）/ calib-low（无盲点表、无后果、无确认）先行验证规则区分度

## 3. 信号判定（D-04 §8 框架）

| 信号 | 判据 | 结果 |
|---|---|---|
| 成功 1：D1 覆盖率 | A 均值 ≥ B + 1.5 且 p<0.05 或 d≥0.8 | 3.80 vs 0.00；p=0.0079；d=12.0 → **成立** |
| 成功 2：D2 问题质量 | A ≥80% 含后果，B ≤50% | 100% vs 0% → **成立** |
| 成功 3：D3 返工风险 | A 漏检 ≤ B 的一半且无致命漏检 | 1.2 vs 5.0；S1 隐私类合规盲点 A 全覆盖（致命漏检=0）→ **成立** |
| 成功 4：D4 确认次数 | A 全部落在 [1,3]（R11 兼容） | 全部 2-3，B 为 0（违反 ≥1）→ **成立**（A 侧无副作用） |
| 失败 1：无显著差异 | 4 维均 p≥0.05 且 d<0.5 | 不成立 |
| 失败 2：副作用 | 长度/确认数/空清单/格式 | 无 |
| 失败 3：规则失效 | 校准未通过 | 校准通过 |

**综合判定：4/4 维度信号成立（≥3 即成功），无副作用 → 成功信号。** 但按 §1.2 的效力边界，正式结论为：

> **"盲点自检提示词注入"在构造性评估下与设计假设一致，且评分管线（case 集/校准/EvalRunner/报告）验证可用；支持设计-1 落地方向。真实模型下的效应量需以同一 case 集走路径 A（LLM API）或路径 B（真实会话）复跑确认。**（三态结论：**有条件支持**——管线证据 + 模拟一致，缺真实效应测量）

## 4. 结论与建议

1. **评分基础设施结论（确定）**：EvalRunner 全链路（EvalCase 96 例 schema 校验、规则断言、EvalReport 绑定、CLI 复跑一致）工作正常；校准样例证明规则能区分高低质量；case 集带版本可复跑。这为后续正式实验提供了即用工具。
2. **提示词效果结论（模拟层级）**：构造性数据 4/4 维度占优，且无副作用（无 token 膨胀、R11 兼容、无空清单）——与 D-02 P1-1/D-03 设计-1 的预期一致，未发现反对落地的信号。
3. **落地建议**：设计-1（task-card 盲点清单节 + SKILL.md 第 7 步）按当前形态落地风险低；正式回归实验（50 次，路径 A）可作为后续 T 任务在获得 API 授权后执行，case 集直接复用（`cases/cases-blindspot.yaml` + `run_experiment.py`）。
4. **限制**：构造性样本存在设计者偏差（执行代理已知种子盲点）；n=5/组仅探索性；单模型效应未测。D-04 §10 威胁缓解（盲评/校准/复跑）在真实路径中保留。
