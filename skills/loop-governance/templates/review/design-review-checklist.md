# 设计审查清单

> **必填表单。** 缺任何必填项 = 打回重做。系统架构师/技术负责人角色必须逐项检查。
> 参考标准：**Google Design Docs Review**、**Google "What to Look For"**、**arc42**。

## 1. 审查信息（必填）

| 字段 | 内容 |
|------|------|
| 审查编号 | DES-REV-YYYY-MM-DD-XXX |
| 设计文档 | [如：system-architecture.md / component-design.md] |
| 设计版本 | [如：v1.2] |
| 设计者 | [角色/姓名] |
| 审查人 | [角色/姓名] |
| 审查日期 | YYYY-MM-DD |
| 审查类型 | [方案评审 / 详细设计评审 / 变更评审] |

## 2. 设计合理性（必查）

| 检查项 | 结果(✅/❌/NA) | 说明 |
|--------|-------------|------|
| 设计目标清晰明确 | [ ] | |
| 明确说明了"做什么"和"不做什么" | [ ] | |

| 每个选择有明确理由（为什么是A不是B） | [ ] | |

## 3. 模块/组件划分（必查）

| 检查项 | 结果 | 说明 |

## 11. 填写示例

> 以"用户认证模块详细设计审查"为例：

| 检查项 | 示例结果 |
|--------|---------|
| 设计目标 | ✅ "实现安全的用户认证，支持JWT令牌管理" |
| 备选方案 | ✅ 比较了 bcrypt/Argon2/PBKDF2，选择了 bcrypt(cost=10) |
| 单一职责 | ✅ 仅负责认证功能，不处理用户资料 |
| 接口完整 | ✅ authenticate/validate_token/revoke_token 定义完整 |
| 数据设计 | ✅ User/Session 实体字段完整，索引合理 |
| 性能 | ✅ 认证 <200ms, 令牌验证 <5ms |
| 安全 | ✅ bcrypt哈希, JWT HS256, 5次锁定, TLS 1.3 |
| 可用性 | ❌ 未说明TokenManager故障时的降级策略（DES-ISSUE-001，中） |
| 测试 | ✅ 单元/集成/E2E 三层覆盖，目标覆盖率 ≥ 80% |
| 文档 | ✅ 结构清晰，有流程图和接口示例 |
| 结论 | 有条件通过：DES-ISSUE-001 需在实现前补充 |
