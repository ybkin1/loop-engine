# 数据迁移方案模板（data-migration-plan）

> **T-0136 D-03 落地。** system-architect 在迁移前填写；迁移方案三件套
> （双写/回滚/校验）缺一不可。**本模板是设计方法论** —— 实际迁移执行
> 属外部边界（forbidden migration），必须用户单独 gate 批准。
> 参考标准：Microsoft Well-Architected Reliability（数据一致性）。

## Part A — 迁移四阶段法

### 阶段 1：准备期
- [ ] 存量数据盘点：行数 / 大小 / 依赖 / 增长速率
- [ ] 停机窗口评估（可接受的最长不可写时间）
- [ ] 校验方案设计（全量比对 or 计数 + 抽样哈希 + 业务对账）

### 阶段 2：迁移期（双写）
- [ ] 双写开关：新老库同时写（老库保底）
- [ ] 存量全量搬迁：分批 + 断点续传 + 速率控制
- [ ] 增量追平：binlog/日志回放，追平延迟 < 目标阈值

### 阶段 3：校验期
- [ ] 双库一致性校验（计数 + 抽样哈希 + 业务对账）
- [ ] 追平延迟确认（lag = 0 或 < 阈值并稳定）

### 阶段 4：切换期（灰度切流）
- [ ] 读流量灰度：1% → 10% → 50% → 100%（每档观察指标）
- [ ] 写流量切换：先非核心写 → 再核心写
- [ ] 保留新老双写 T 天（回滚窗口）

## Part B — 回滚方案

| 项 | 内容 |
|----|------|
| 触发条件（预定义） | 错误率 > X% / 校验不一致 > Y 条 / RT 恶化 > Z% |
| 回滚动作 | 读回切老库 + 写回切老库；新库数据保留可复盘 |
| 回滚验证 | 老库恢复服务 + 数据完整性复查 |
| 回滚窗口 | 双写期 = 天然窗口；切换后保留 T 天反向同步 |

## Part C — 数据不丢失（三层保证）

1. **双写幂等**：唯一键/版本号（防重放）
2. **搬迁断点续传**：批次记录 + 校验和
3. **增量追平水位**：lag 监控 + 追平失败告警
4. **终极对账**：切换后 24h 新老库持续对账 → 不一致自动告警 + 补偿任务

## Part D — 单体→微服务拆分迁移专项

- **数据边界先行**：先拆库表归属（每服务只能访问自己的表），再拆代码
- **业务无感知**：接口兼容层（旧接口代理新服务）+ 灰度放量 + 影子流量
  对比（新老逻辑双跑，结果比对）
- **迁移顺序**：读多写少 → 读写均衡 → 写多读少（风险递增）

## 本模板填写项

| 字段 | 内容 |
|------|------|
| 迁移目标 | 引擎/库/表 + 原因（容量/性能/成本/能力） |
| 存量规模 | 行数/大小/增长 |
| 双写方案 | 开关/幂等键/回放机制 |
| 校验方案 | 计数 + 抽样哈希 + 对账 |
| 灰度切流档位 | ≥3 档 + 每档验证指标 |
| 回滚方案 | 触发条件 + 动作 + 窗口 |
| 演练记录 | 注入异常 → 回滚 → 恢复 |

## 角色指引

- **谁填**：system-architect（迁移方案）；quality-engineer（校验设计）
- **谁审**：release-engineer（切流执行与回滚）；delivery-manager（GO/NOGO）
- **边界**：实际执行必须用户单独 gate（外部边界不豁免）
