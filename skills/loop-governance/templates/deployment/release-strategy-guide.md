# 发布策略决策指南（release-strategy-guide）

> **T-0136 D-06 落地。** release-engineer / delivery-manager 在发布前选择
> 策略时使用。决策输入四要素必须留档。

## 1. 策略决策矩阵

| 策略 | 适用场景 | 不适用 |
|------|---------|--------|
| 灰度发布 | 用户量可切分、需按用户维度放量观察（功能开关） | 数据不可分割 |
| 蓝绿发布 | 环境切换快、需整体回滚（数据库兼容双版本） | 大版本不兼容变更 |
| 金丝雀 | 新版本风险高、小流量验证（按比例/按特征） | 无监控体系 |

## 2. 决策输入（四要素，必须留档）

1. **变更风险等级**：高（DB 变更/核心链路/协议变更）→ 金丝雀或蓝绿
2. **回滚能力**：能否快速回滚（应用级 yes / 数据级 no）→ 决定蓝绿可行性
3. **数据兼容性**：新旧版本数据 schema 是否兼容 → 不兼容必须蓝绿+双写
4. **可观测性**：监控告警是否就绪 → 无监控不做金丝雀

## 3. 决策流程

```
风险高？
 ├─ 是 → 可观测？ → 是 → 金丝雀（按比例/特征）
 │                  └ 否 → 先补监控再发布
 ├─ 否 → 数据兼容？
 │        ├─ 否 → 蓝绿 + 双写（或灰度+兼容层）
 │        └─ 是 → 用户可切分？ → 是 → 灰度（功能开关）
 │                               └ 否 → 蓝绿
```
