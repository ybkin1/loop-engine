# Loop 工程素材库

状态：`candidate / research-baseline-v0.1`

本目录是 Loop 正式实现前的外部工程知识库。它保存可追溯的来源、工程方法、模板骨架、可执行工具和 Loop 适配说明，供后续的角色合同、Phase Profile、Quality Profile、提示词和检查器组合使用。

素材库不是运行时规则，也不是“把所有资料拼进上下文”的提示词包。每条素材必须先经过来源核验、适用性判断和项目配置；只有用户批准对应的项目 Gate 后，才可成为该项目的执行约束。

## 目录

- `catalog.yaml`：机器可检索的材料登记表。
- `material-schema.yaml`：材料登记字段与枚举约束。
- `source-register.yaml`：逐条来源核验的机器可读 canonical register。
- `source-register-schema.yaml`：来源 register 的字段、枚举和条件约束。
- `source-register.md`：canonical register 的 46 条人读投影、来源层级和人工阅读索引。
- `coverage-matrix.md`：工程领域覆盖、已登记素材和待补缺口。
- `templates/`：可组合的项目交付物模板，不是某个项目的成品。
- `frameworks/`：方法论如何转换为 Loop 可执行配置的说明。
- `profiles/`：候选的项目类型、阶段和质量配置样例。
- `profiles/material-selection-record.yaml`：每个项目选择、拒绝和裁剪素材的记录。
- `templates/role-capability-probe.yaml`：验证角色能力声明的任务集模板。

## 来源层级

1. `E1`：可直接读取的官方规范、官方文档或官方工具说明。
2. `E2`：权威机构的标准入口、官方摘要或正式出版物入口；正文可能受访问或版权限制。
3. `E3`：成熟工程实践、开源项目文档或行业方法论；必须标注适用边界。
4. `E4`：研究论文、实验性 Agent 方法或 Loop 自定义设计；不能单独作为生产门禁。

来源等级不等于项目结论。素材只回答“可参考什么、何时用、如何产出、有什么限制”，不替项目经理、架构师、质量工程师或用户作决定。

## 组合流程

```text
用户意图
  -> 项目类型与风险画像
  -> 检索 catalog.yaml
  -> 选择来源 + 方法 + 模板 + 工具
  -> 形成 project-profile / phase-profile / quality-profile
  -> 角色独立评审
  -> 用户 Gate 批准
  -> 项目执行与证据回收
```

## 使用规则

- 不把博客、标准、模板、工具和 Loop 自定义规则放进同一层。
- 不因一条提示词“看起来专业”就将其当作能力证明；必须绑定输入、输出、检查器和失败处理。
- 不把覆盖率、模型自报、评审 PASS 或构建成功单独当成交付证明。
- 素材版本、来源状态和适用边界发生变化时，项目配置必须重新评估。
- 模板允许项目化裁剪，但裁剪理由、删除项和替代证据必须记录。

## 当前边界

本版本完成主要工程域的研究基线和模板骨架；未声称穷尽所有国家标准、行业法规、语言生态或宿主 Agent 能力。未核验、访问受限和仅有入口页的来源会明确标记，不能被当成已读正文。
