# 从外部工程知识到 Loop 约束

素材进入 Loop 的路径必须是分层转换，而不是复制粘贴：

```text
原始来源
  -> 适用性摘要
  -> 项目问题与风险
  -> 可交付物模板
  -> 角色职责/阶段活动
  -> 确定性检查器
  -> 证据和否决条件
  -> 用户 Gate
```

## 转换表

| 来源层 | 允许产生 | 不允许直接产生 |
| --- | --- | --- |
| 标准/规范 | 要求、术语、过程、控制目标 | 自动通过、项目适用性结论 |
| 官方指南 | 候选做法、参数和示例 | 跨技术栈的硬规则 |
| 方法论 | 工作流原则、角色协作方式 | 不经裁剪的全流程 |
| 模板 | 交付物结构和字段 | 已完成的项目事实 |
| 工具文档 | 命令、输入输出、执行证据 | 工具成功等于产品质量 |
| 研究论文 | 实验候选、假设、评估设计 | 生产可靠性承诺 |
| Loop 适配层 | 角色、阶段、证据和 Gate 组合 | 冒充外部标准或用户批准 |

## 每次组合的最小问题

1. 这条素材解决哪个具体项目风险？
2. 输入是否已批准、可追溯且没有秘密？
3. 输出是否有 Schema、示例和失败结果？
4. 哪个角色独立检查它？检查器如何执行？
5. 失败时是修复、阻断、降级还是交给用户？
6. 该规则的版本、有效期、替代来源和重议条件是什么？
