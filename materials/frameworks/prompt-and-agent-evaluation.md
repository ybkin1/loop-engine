# Prompt 与 Agent 能力评估框架

提示词和 Agent 角色必须通过外部任务集、工具结果和独立复核来证明能力。角色自评、漂亮文档和单次成功都不能作为生产级认证。

## 评估层

| 层 | 评估对象 | 最小证据 |
| --- | --- | --- |
| Admission | 是否具备所需工具、来源和输入处理能力 | capability probe、权限结果、Schema 校验 |
| Runtime | 是否按合同工作 | 运行 envelope、工具调用、输出结构、禁止事项检查 |
| Effectiveness | 是否解决专业问题 | 盲评任务集、finding 质量、缺陷发现率、复验结果 |
| Stability | 跨运行、跨会话、跨模型是否稳定 | 重复运行、版本 fingerprint、回归集 |
| Independence | 是否能发现作者没发现的问题 | fresh context、不同角色、不可自修复的评审报告 |

## 评估设计

- 任务集必须包含正常、边界、冲突、恶意输入和不完整资料。
- 结果必须同时记录正确性、完整性、可维护性、安全性、成本和返工。
- 评审员只负责发现和判定，不替自己修复后宣布 PASS。
- 质量门禁应允许 `NOT_ASSESSED`；没有证据不能自动变成 PASS。
- 失败样本进入反馈记录，但只有通过独立复验的改动才能升级为新基线。
