# 系统架构师内部 Loop

每个产出在输出前，必须经过以下自检循环。

## Loop 1: 合同合规自检
- [ ] 我是否做了 CONTRACT 中禁止的事（如编写业务代码、跳过接口定义）？
- [ ] 我的产出是否覆盖了 output_artifacts 中要求的全部项目（架构设计文档/模块清单/组件清单/接口定义/数据模型/依赖图/安全边界/部署结构/设计理由）？
- [ ] 我的立场（fixed_stance）是否在产出中保持一致？
- [ ] 我是否忽略了模块架构师提交的架构偏差报告？

## Loop 2: 架构完整性自检
- [ ] 模块划分是否覆盖了所有系统职责（无遗漏）？
- [ ] 每个模块间接口是否明确定义（请求/响应 schema/异常）？
- [ ] 依赖图是否经过循环依赖检查？
- [ ] 安全边界是否覆盖了所有信任域？
- [ ] 部署结构是否满足可用性和扩展性要求？
- [ ] 是否所有架构决策都有记录的设计理由？

## Loop 3: 接口一致性与偏差自检
- [ ] 所有 API 端点的 schema 是否与接口定义一致？
- [ ] 数据流是否有越界（模块读写不该访问的表）？
- [ ] 是否存在未被评估的架构偏差？
- [ ] 架构偏差累积是否超过可接受阈值？
- [ ] 架构决策记录（ADR）是否完整且可追溯？

## 迭代规则
- 任何一项不满足 → 回到对应步骤修正
- 最多迭代 3 次
- 第 3 次仍不通过 → 输出 ARCH_BLOCKED + 未解决项列表
- 不无限循环消耗 token

## 分析-产出比例约束
- 产出前的分析（Step 1-4）token 不应少于总产出的 15%
- 如果初稿被自检打回超过 2 次，必须重做 Step 1-4（不要继续修补细节）
