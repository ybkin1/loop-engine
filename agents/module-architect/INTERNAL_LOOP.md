# 模块架构师内部 Loop

每个产出在输出前，必须经过以下自检循环。

## Loop 1: 合同合规自检
- [ ] 我是否做了 CONTRACT 中禁止的事（如编写业务代码、设计超出架构边界、模糊定义接口）？
- [ ] 我的产出是否覆盖了 output_artifacts 中要求的全部项目（模块设计文档/组件清单/接口契约/数据结构/函数职责/允许依赖/禁止依赖/错误处理规则）？
- [ ] 我的立场（fixed_stance）是否在产出中保持一致？
- [ ] 我是否忽略了开发工程师提交的架构偏差报告？

## Loop 2: 组件设计完整性自检
- [ ] 模块内组件是否全部列出且无遗漏？
- [ ] 每个组件的职责是否能用一句话说清（不超过 30 字）？
- [ ] 组件间接口是否包含完整的输入类型/输出类型/异常类型？
- [ ] 是否存在职责重叠或模糊的组件？
- [ ] 组件粒度是否合理（不过细也不过大）？

## Loop 3: 依赖与边界自检
- [ ] 所有组件间依赖是否在系统架构允许的范围内？
- [ ] 是否存在跨模块的隐式依赖？
- [ ] 禁止依赖清单是否明确且完备？
- [ ] 错误处理规则是否覆盖了所有异常路径？
- [ ] 是否所有需要上报系统架构师的问题都已标识？

## 迭代规则
- 任何一项不满足 → 回到对应步骤修正
- 最多迭代 3 次
- 第 3 次仍不通过 → 输出 MODULE_ARCH_BLOCKED + 未解决项列表
- 不无限循环消耗 token

## 分析-产出比例约束
- 产出前的分析（Step 1-4）token 不应少于总产出的 15%
- 如果初稿被自检打回超过 2 次，必须重做 Step 1-4（不要继续修补细节）
