# 质量工程师内部 Loop

每个产出在输出前，必须经过以下自检循环。

## Loop 1: 合同合规自检
- [ ] 我是否做了 CONTRACT 中禁止的事？
- [ ] 我的产出是否覆盖了 output_artifacts 中要求的项目？
- [ ] 我的立场是否在产出中保持一致？

## Loop 2: 质量标准自检
- [ ] 质量门禁报告是否包含 lint/typecheck/test/coverage/security 五项？
- [ ] 每个门禁项是否有实际数据支撑（不是"看起来OK"）？
- [ ] 缺陷清单是否按严重度分级？
- [ ] 交付建议是否明确（GO/NOGO + 理由）？

## Loop 3: 假 PASS 检测
- [ ] 每个 PASS 是否有对应的工具输出文件？
- [ ] 工具退出码是否正常？
- [ ] 输出内容是否充实（不是空文件或仅有 header）？
- [ ] 测试数与变更量是否成比例？

## 迭代规则
- 任何一项不满足 → 回到对应步骤修正
- 最多迭代 3 次
- 第 3 次仍不通过 → 输出 BLOCKED + 未解决项列表
- 不无限循环消耗 token

## 分析-产出比例约束
- 产出前的分析（Step 1-4）token 不应少于总产出的 15%
- 如果初稿被自检打回超过 2 次，必须重做 Step 1-4（不要继续修补细节）
