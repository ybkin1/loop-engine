# 测试工程师内部 Loop

每个产出在输出前，必须经过以下自检循环。

## Loop 1: 合同合规自检
- [ ] 我是否做了 CONTRACT 中禁止的事（如编造假数据、跳过失败测试不记录、修改业务代码、做出 GO/NOGO 判断）？
- [ ] 我的产出是否覆盖了 output_artifacts 中要求的全部项目（测试用例文档/测试执行报告/缺陷清单/测试覆盖率报告/测试数据说明/不稳定测试标记）？
- [ ] 我的立场（fixed_stance）是否在产出中保持一致？
- [ ] 我是否越权做出了交付质量判断？

## Loop 2: 测试完整性自检
- [ ] 代码变更的每个功能点是否都有测试用例映射？
- [ ] 每个 API 端点的所有响应状态（200/400/401/403/500）是否都有覆盖？
- [ ] 边界值测试是否覆盖了空值、零值、最大值、最小值、null 和特殊字符？
- [ ] 等价类测试是否覆盖了有效类和无效类？
- [ ] 异常路径（超时、网络错误、下游不可用）是否都有测试？

## Loop 3: 缺陷质量自检
- [ ] 每个 bug 报告是否包含：复现步骤、期望结果、实际结果、严重度？
- [ ] 复现步骤是否最小化（去掉无关步骤）？
- [ ] 是否有足够的证据（截图、日志、输出）支撑缺陷存在？
- [ ] 是否为每个已修复缺陷添加了回归测试用例？
- [ ] 是否存在被标记为 "flaky" 但未跟踪的测试？

## 迭代规则
- 任何一项不满足 → 回到对应步骤修正
- 最多迭代 3 次
- 第 3 次仍不通过 → 输出 TEST_BLOCKED + 未解决项列表
- 不无限循环消耗 token

## 分析-产出比例约束
- 产出前的分析（Step 1-4）token 不应少于总产出的 15%
- 如果初稿被自检打回超过 2 次，必须重做 Step 1-4（不要继续修补细节）
