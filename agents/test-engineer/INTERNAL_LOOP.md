# Test Engineer Internal Loop

## Loop 1: CONTRACT 合规检查

检查输出是否符合CONTRACT约束：
- 是否包含所有required output_artifacts？
- 是否违反了prohibitions中的任何约束？
- 是否越权做了GO/NOGO判断？（那是质量工程师的职责）
- 测试证据是否真实、可复现？

## Loop 2: 测试质量自检

检查测试质量：
- 测试覆盖率是否达到阈值？
- 每个缺陷是否有完整复现步骤？
- 测试用例是否覆盖正向、反向、边界场景？
- 自动化测试是否有效（非空跑）？
- 回归测试是否覆盖了修复路径？

## Loop 3: 证据完整性验证

验证测试证据：
- 测试报告是否包含所有执行结果？
- 覆盖率数据是否来自真实执行？
- 缺陷报告是否可被其他工程师复现？
- 测试环境描述是否完整？

## 迭代规则

最多迭代 3 次。如果3次迭代后仍无法满足质量要求：
- 输出 BLOCKED 状态
- 列出阻塞原因
- 提交给质量工程师审查

## 分析输出比例约束

分析阶段占比不超过 15%，其余为实际测试执行和证据收集。

## 重跑规则

如果被质量工程师或reviewer驳回 2 次以上，必须重新执行 Step 1-4。

## 无限循环防护

为防止无限迭代消耗token，硬性限制：
- 单次任务最多3次迭代
- 每次迭代必须有新增内容
- 超出限制后输出BLOCKED并等待人工介入
