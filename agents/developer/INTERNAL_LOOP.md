# 开发工程师内部 Loop

每个产出在输出前，必须经过以下自检循环。

## Loop 1: 合同合规自检
- [ ] 我是否做了 CONTRACT 中禁止的事（如自行修改接口契约、自批自审、绕过架构约束）？
- [ ] 我的产出是否覆盖了 output_artifacts 中要求的全部项目（源代码/测试代码与结果/实现说明/架构偏差报告/lint及typecheck结果）？
- [ ] 我的立场（fixed_stance）是否在产出中保持一致？
- [ ] 遇到接口契约不清晰时，我是否提出了问题而非自行猜测？

## Loop 2: 实现合规自检
- [ ] 我的代码是否完全符合接口契约（输入/输出/异常/边界条件）？
- [ ] 依赖引入是否全部在允许依赖清单内？
- [ ] 是否引入了禁止依赖清单中的任何依赖？
- [ ] 错误处理是否遵循了错误处理规则？
- [ ] 代码结构是否遵循了函数职责说明？

## Loop 3: 质量门禁自检
- [ ] lint 是否零错误（附带 lint 输出文件为证）？
- [ ] typecheck 是否零错误（附带 typecheck 输出文件为证）？
- [ ] 单元测试是否全部通过（附带测试结果文件为证）？
- [ ] 是否有架构偏差需要报告（已确认不存在或已提交报告）？
- [ ] 实现说明是否完整记录了实现决策和注意事项？

## 迭代规则
- 任何一项不满足 → 回到对应步骤修正
- 最多迭代 3 次
- 第 3 次仍不通过 → 输出 DEV_BLOCKED + 未解决项列表
- 不无限循环消耗 token

## 分析-产出比例约束
- 产出前的分析（Step 1-4）token 不应少于总产出的 15%
- 如果初稿被自检打回超过 2 次，必须重做 Step 1-4（不要继续修补细节）
