# 排期冲突与取舍检查清单（delivery-manager）

> **T-0136 D-06 落地。** 交付经理在需求排期冲突时使用。
> 配套升级协议：`docs/09-escalation-protocol.md`（唯一升级通道）。

## 排期冲突处理范式（面试题：1 个月 vs 2-3 个月改造）

1. **拆解**：找出 1 个月内可达的最小可交付切片（MVP 切分）——
   按 P0 安全/数据风险 > P1 稳定性 > P2 性能 > P3 维护性
2. **对齐**：向用户呈现「完整改造 vs 分期」取舍 —— 走升级协议第 1 类
   （产品取舍），选择题形态 + 推荐 + 理由
3. **兜底**：技术债登记（KNOWN_ISSUES）+ 后续任务排布

## 技术债优先级（面试题：老系统不能改怎么排）

| 优先级 | 类型 | 处理 |
|--------|------|------|
| P0 | 安全/数据风险 | 立即修（无豁免） |
| P1 | 稳定性（故障面） | 近期排期 |
| P2 | 性能 | 按影响排期 |
| P3 | 维护性 | 债务账本登记 |

**无法修改的老系统** → 隔离 + 监控 + 封装（防腐层），不强行重构。

## 必查项

- [ ] MVP 切分已做（1 个月内可达的最小切片）
- [ ] 取舍走升级协议（选择题 + 推荐 + 理由），未私自定义
- [ ] 无法即时修复项已登记 KNOWN_ISSUES/债务账本
