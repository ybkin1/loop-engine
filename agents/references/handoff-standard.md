# 角色间交接协议标准

本文定义了角色 A 把产出交给角色 B 时，B 验收 A 的标准流程。

## 交接四件事

每次角色间交接，必须包含以下四样东西。缺任何一样，下游有权拒收。

### 1. 交付包（上一个角色的输出）

直接引用角色输出文件路径。不转述、不摘要——下游自己读原文件。
如果上游的输出有多个文件，列出全部。

### 2. 验收标准（下游角色合同中"上游验收"节的内容）

这是下游角色在合同里写的"我接收上游产出时的标准"。
不是上游自己觉得"做得不错"的标准。

### 3. 验收结果（下游角色执行的判断）

验收结果只有三种：
- **通过**：下游确认上游产出满足自己的验收标准，可以开始工作
- **拒收**：上游产出不满足验收标准，附带具体原因和合同条款引用
- **有条件通过**：上游产出基本满足，但有 N 个待补项——下游可以开始但不保证
  不会在后面打回来

> 注意："有条件通过"不是"勉为其难放一马"。待补项必须在下一阶段 gate 前补齐，
> 否则质量工程师会在那个点拒收。

### 4. 验收记录（写入证据目录）

每次交接产出一份 `handoff-record.md`，写入 `.ai/evidence/<phase>/`，
包含：上游角色 + 产出路径、下游角色 + 验收标准引用、验收结果 + 理由、时间戳。

## 交接链

标准的项目交接链（各项目根据阶段裁剪）：

```
产品经理 → 项目经理
    ↓
项目经理 → 系统架构师
    ↓
系统架构师 → 模块架构师
    ↓
模块架构师 → 开发工程师
    ↓
开发工程师 → 质量工程师
    ├→ 安全工程师
    └→ 独立代码评审员
        ↓
质量工程师 + 安全工程师 + 独立评审员 → 交付经理
    ↓
交付经理 → 发布工程师
    ↓
发布工程师 → 交付经理（发布确认）
```

每个箭头对应一次验收。下游有权打回上游。打回后上游返工，
重新走交接四件事。

## 交接中的冲突

如果上游被下游拒收后认为"下游的标准不合理"：
- 走 `role-conflict-protocol.md` 的 B 类冲突处理
- 上下游继续在各自的合同条款内工作——不会因为冲突而停工
- 上游可以基于"我不同意标准"继续输出，但要标注待决议

## 时间盒（可选，按项目调整）

如果项目需要控制进度：
- 交接验收必须在 N 小时内完成（N 由项目经理在阶段计划中指定）
- 拒收必须在接收到交付包后 N 小时内发出（过时不拒收视为通过）
- 返工必须在拒收发出后 M 小时内完成

> 以上时间盒仅在项目经理的合同里定义了才生效。
> 没有项目经理的阶段计划，时间盒不存在——角色不能自己给自己设时限。
