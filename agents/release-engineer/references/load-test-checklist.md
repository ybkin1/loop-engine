# 压测验收检查清单（release-engineer）

> **T-0136 D-01 落地。** 发布工程师在发布前核对压测证据。
> 配套模板：`skills/loop-governance/templates/capacity/load-test-plan.md`

## 必查项（缺任一 = NOGO 候选）

- [ ] 压测报告存在（含时间/环境/目标场景）
- [ ] 覆盖目标 QPS（日常 + 活动峰值场景；有 ≥10× 峰值的必须做峰值压测）
- [ ] 四指标合格线逐项 PASS（目标 QPS / p99 ≤ 3× 基线 / 错误率 <0.1% /
      CPU ≤ 70%）
- [ ] 容量拐点已测并记录（或说明为何不需测）
- [ ] 防污染证据（影子库/标记流量说明 + 生产残留对账）
- [ ] 结论 PASS 或附条件（附条件需 delivery-manager 裁决）

## 常见驳回场景

- "上线后再压" → 驳回：压测是发布前置活动（与监控同原则）
- 只测平均不测 p99 → 驳回：长尾决定体验
- 无防污染说明 → 驳回：影子流量泄漏生产 = 数据事故
- 峰值场景缺失（有活动业务但只测日常） → 驳回
