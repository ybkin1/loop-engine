# 稳定性发布检查清单（release-engineer）

> **T-0136 D-02 落地。** 发布工程师在发布前核对稳定性证据。
> 配套模板：`skills/loop-governance/templates/stability/resilience-design.md`

## 必查项（缺任一 = NOGO 候选）

- [ ] 核心链路熔断配置存在（错误率阈值 + 最小请求量 + 半开恢复窗口）
- [ ] 阈值推导文档存在（SLO 反推或基线实测）
- [ ] 降级演练记录（注入故障 → 验证降级 → 恢复判定）
- [ ] 超时配置 ≤ 下游 p99 的 50%（防排队雪崩）
- [ ] 降级方案明确用户体验预期

## 常见驳回场景

- 熔断阈值"抄网上的"无推导 → 驳回
- 只有熔断配置无演练记录 → 驳回（配置不可信）
- 核心链路无降级方案 → 驳回
