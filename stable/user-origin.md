# User Origin

用户是非代码背景，希望借助 Qoder 跨会话稳定推进复杂软件项目，最终产出真实可用、可部署、可验收、可持续迭代的软件。

Qoder 需要同时承担产品经理、项目经理、开发经理、交付经理的部分职责：从粗略甚至有产品逻辑问题的需求开始，帮助用户澄清、立项、设计、拆分任务、执行、验证、交付和持续迭代。

当前讨论重点不是直接实现某个业务项目，而是设计一套 loop 工程机制，让主线程可以通过一次性 subagent 完成写作、评审、修订和交接循环，降低用户手动切换会话和复制粘贴的负担。

必须防止：

- 跨会话遗忘。
- 项目理解漂移。
- 代码风格、接口、协议、技术选型不一致。
- Qoder 越权写文件或安装协议。
- 局部完成冒充产品完成。
- 自动化测试、review、CI 被误当成用户批准。
- 文档越来越重但产品仍不可用。
- 旧工具、Skill、MCP、agent 抢协议权威。
- current 或 handoff 被误用来扩大权限。
