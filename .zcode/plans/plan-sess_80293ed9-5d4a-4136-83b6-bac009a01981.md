## 模块一：变更迭代支持（核心新增能力）

### 1.1 变更意图识别 — 增强 `loop_core/intent_router.py`

**现状**：`IntentRouter.analyze()` 只能判断"新项目"，无法区分变更类型。

**新增**：

```python
class ChangeType(str, Enum):
    NEW_PROJECT = "new_project"        # 全新项目
    BUG_FIX = "bug_fix"               # 修复缺陷
    FEATURE_ADD = "feature_add"        # 新增功能
    REFACTOR = "refactor"              # 重构优化
    REQUIREMENT_CHANGE = "requirement_change"  # 需求变更
    QUALITY_FIX = "quality_fix"        # 质量修复
    UNKNOWN = "unknown"                # 无法判断
```

`IntentAnalysis` 新增字段：
- `change_type: ChangeType` — 变更类型
- `is_existing_project: bool` — 是否已有项目
- `suggested_entry_phase: Phase` — 建议入口阶段
- `affected_modules: list[str]` — 受影响的模块
- `requires_full_loop: bool` — 是否需要全流程重走
- `evidence_invalidation: list[str]` — 需要失效的证据

**路由规则**：

| 变更类型 | 入口阶段 | 最小 Loop | 证据处理 |
|---------|---------|----------|---------|
| NEW_PROJECT | S0-init | FULL | — |
| BUG_FIX | S9-fix-optimize | S9→S5→S4(修复)→S5→S6 | 相关测试证据失效 |
| FEATURE_ADD | S4-implementation | S3(接口)→S4→S5→S6 | 相关接口证据失效 |
| REFACTOR | S4-implementation | S4→S5→S6 | 全部实现证据失效 |
| REQUIREMENT_CHANGE | S1-requirements | FULL | 全部下游证据失效 |
| QUALITY_FIX | S5-quality | S5→S6 | 质量证据失效 |

### 1.2 变更路由 — 增强 `loop_core/executor.py`

**新增 `reentry_phase()` 方法**：
```python
def reentry_phase(self, change_type, affected_modules) -> Phase:
    """Determine which phase to re-enter based on change type."""
```

**新增 `invalidate_evidence()` 方法**：
```python
def invalidate_evidence(self, modules, evidence_types) -> list[str]:
    """Mark affected evidence as STALE."""
```

**增强 `execute_phase()`**：
- 支持从中途阶段开始（不只是从 current_phase 顺序推进）
- 变更结束后自动回到 `S6-delivery` 做交付判断

### 1.3 已发布 vs 未发布 — 增强 `loop_core/state_machine.py`

**新增 `ProjectStatus` 枚举**：
```python
class ProjectStatus(str, Enum):
    DRAFT = "draft"           # 未发布，可自由修改
    RELEASED = "released"     # 已发布(git tag)，变更需走完整流程
    MAINTENANCE = "maintenance"  # 维护模式
```

**新增约束**：
- `RELEASED` 项目：禁止跳过评审和质量门禁
- `DRAFT` 项目：允许 mini-loop 快速迭代
- 写入 `state.yaml` 时检查项目状态

## 模块三：Bash 拦截增强（REPAIR-6）

**现状**：`has_write_operations()` 有已知覆盖缺口。

**新增检测**：
- `curl/wget -O` → 文件下载写入
- `pip install` → 包安装（可能覆盖文件）
- `git clone/fetch/pull` → 仓库变更
- 管道写入 `| tee` / `| dd of=`
- `openssl enc` → 文件加密写入
- `tar -x` / `unzip` → 解压覆盖

**新增配置文件**：`.zcode/skills/loop-governance/config.yaml` 增加 `bash_interception` 节：
```yaml
bash_interception:
  strict_mode: false  # true=未知命令默认阻断
  allowlist: []
  blocklist: []
```
